# Ingress allowlist (operator-owned)

`~/.shepy/ingress-allowlist.json` is owned and maintained by the operator, not the router or scanner. Missing, unreadable or invalid configuration refuses demand admission. Do not put credentials in the file. An admitted same-user Unix socket client can claim any configured `sourceId`: that string is **not** process authentication. Keep this allowlist narrow and review changes before deploying a daemon that exposes `inbox.publishDemand`.

The `shepy.ingress-allowlist.v1` document contains `sources`, keyed by source id. Each entry lists `profiles`, `kinds`, `duty_paths`, `grant_hashes`, `evidence_roots`, and `max_expiry_minutes` (at most 60). For demand eligibility, it also supplies `seat_state_path`: the absolute operator-pinned live `factory.seat-state.v1` observation file. Without this path, publication refuses; the producer cannot select it in a request. The sole duty contract is the strict `factory.duty.v1` in the router spec §3, not the superseded short duty-schema file. The operator must update it when grants, duty paths, or admission windows change and revoke obsolete entries; producers may not edit it. Publication and every duty lease must re-read it. The phase-2 eligibility provider refuses an empty `grant_hashes` array: the strict duty grant must be explicitly pinned by the operator. The phase-1 validator alone is not an eligibility decision.

The source implementation provides the daemon socket RPCs and a daemon-owned demand-event/obligation transaction; publication and lease re-read the allowlist and duty/capacity files. Only a first-revision routine `queue-claimable` activation is eligible: continuation-missing, successor-escalation and later activation revisions fail closed until a verified continuation/disposition and successor route are implemented. The request schema accepts those forms for validation but does not authorize their delivery. An agent-only owner remains agent-only until it explicitly claims the `profile-demand` capability through a demand-capable client. This source build is **not** a daemon deployment or a live canary; there is no automatic scanner/router producer or seat-side action grant. Demand obligation transport acknowledgement is not a continuation disposition.
